# Direction

The shipped direction is a thin coordinator, not an autonomous delivery engine:

- SPARK methodology and conversational approval.
- Native pi-subagents execution with exact configured model routes.
- Task-local checks and fresh combined review, plus security for sensitive tasks.
- Optional native browser capability probes and source-bound readable verifier evidence.
- Separately approved one-attempt evidence-only recovery; no accepted coder/check replay.
- Bounded corrections, final checks after all tasks, actual evidence in reports.
- Read-only reviews, preserved dirty work, known worker identity and conservative stop/monitoring.

Optimizer passes, dev/full profiles, alternate review policies, automatic branch/push/merge lifecycle, cleanup, candidate adoption and general recovery/migration are intentionally removed, not future modes. Historical plans under `docs/spark` document earlier directions and must not be used as operational prompts.

Future changes should improve small contract tests, actionable diagnostics and native compatibility without rebuilding execution machinery. No unimplemented capability is an execution promise.

Shipped evidence recovery requires new typed checkpoints and exact closure/fence proof. Old journals are not promised recoverable. OFF is a settled unmanaged handoff that invalidates recovery, not a reset/retry mechanism. Native/browser/provider live end-to-end verification remains separate from offline contract tests.
