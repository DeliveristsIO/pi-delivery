# Incident replays and effective configuration reporting

Keep delivery a thin coordinator. Adopt failure-derived test fixtures and honest configuration reporting without adding a scheduler, memory service, watchdog, or execution engine.

`delivery_configure` inspection will retain its routes/catalog fields and add effective active settings plus names of ignored compatibility/unknown fields. Report planning/coder/quality/security routes, approval mode, commits, and command timeout. Do not print ignored values. Share timeout validation with execution so inspection cannot imply an invalid timeout works. Preserve config files and existing defaults.

Replay fixtures describe sanitized, reconstructed failure scenarios already represented in the repository's contracts. They are explicitly not verbatim production transcripts. Script reports/check exits through the existing isolated extension harness; assert blocked/complete outcomes, permitted launches, actual receipts, and absence of false completion. Do not launch live models or add a second harness. Future real incidents should record provenance without credentials or private source.

Done: configure accurately describes defaults, configured behavior, and inert fields; incident replays exercise evidence failures and a positive completion control; existing checks pass. No imported third-party implementation or skill is needed.
