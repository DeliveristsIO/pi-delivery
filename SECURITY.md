# Security boundaries

Delivery is a trusted-session coordinator, **not an OS sandbox**. Pi extensions share process/account permissions. Load only trusted extensions, agents, providers and repositories. Report security issues privately to the repository maintainer; do not include credentials, transcripts or private project paths in public issues.

## Controls

- No writer launches before explicit user approval of a displayed unchanged plan. Exact configured model routes and workspace snapshot are bound to that proposal.
- One native writer at a time; an exclusive canonical-workspace lock prevents concurrent delivery owners. Same-process reload may monitor its exact retained live worker. Full-restart reclaim requires the same parent session UUID/delivery run, a conclusively dead previous owner and exact native ID/directory/owner with validated observed `process-terminal.json` proof (runner close and any writer process-tree closure). Lock operations serialize/revalidate under an exclusive guard; unknown guard ownership blocks. A matching journal fence rotates on acquisition and before consuming a worker can advance to subsequent work; stale copies cannot reclaim using an earlier worker's closure. Legacy missing fences never match a lock rewritten by this code. Living/unknown owners or workers, pending checks, malformed/missing proof and foreign identities cannot unlock. Other tools/processes outside delivery do not honor this lock.
- Reviewers are fresh native sessions with strict `read`, `grep`, `find`, `ls` allowlists and explicit shell/write exclusions. Review mode executes no host checks and no fixes. Agent/settings overrides and installed runtime code remain trusted configuration; do not broaden those profiles.
- The coordinator session keeps its own tools (shell, writes, delegation) while delivery is enabled so it can always finish the task; coordinator edits inside an active worker's approved scope are detected by snapshot evidence and block that run. Coordinator Git helpers use fixed read-only arguments, disable external diff/text conversion and refuse configured clean/process filters.
- Native completion requires matching run/session/agent/model evidence, terminal process proof and a valid structured report. Check receipts contain actual host exit codes/output. No activity or model claim is treated as verification.
- Task files are starting points, not a permission list. Coder snapshots accept additional repository edits, but never index/HEAD changes or changed symlinks. Review/check snapshots remain strictly unchanged. Symlink ancestors are rejected; workers must not traverse symlinks or edit external targets.
- Actual changed paths accumulate per task across corrections for independent product-intent review. Unrelated edits, new requirements/dependencies/provider changes and destructive actions remain unauthorized. The configured security route is bound before implementation approval, including conditional review for newly discovered sensitive paths; no automatic model selection or reconfiguration occurs.
- Dirty work is preserved without cleanup, Git writes, stash or baseline commits. Reviewers receive preexisting work evidence and must distinguish it from task changes, including within touched files. Preservation and task relevance are instruction/review boundaries, not a guessed path allowlist. Violations stop for inspection, never automatic rollback. Snapshots cover tracked/untracked nonignored regular files and symlink identities; ignored files and external targets are not covered. Baseline evidence is a bounded diff/status preview, not a full content backup; untracked content is not archived.

## Remaining trust

Approved commands and coder shell tools run with your account permissions. They can execute project scripts and access files/network; prompts prohibit Git writes and unrelated edits but cannot sandbox arbitrary shell. Approve only commands and repositories you trust. Built-in read tools may read beyond the workspace; avoid secrets in task context. Runtime artifacts, session records and provider requests may contain source and check output. Do not publish them.

Infrastructure failures stop. `delivery_stop` requests native cancellation; acknowledgement is not process closure. `delivery_resume` observes only the retained worker without new approval, using the same implementation as the slash commands. No revival, replacement from arbitrary text, PID killing, force unlock, or replay of accepted work. A prior stop request or native stopped outcome remains stopped; failed outcomes are not automatically retried. Terminal status/PID death alone are not proof. Installed native proof depends on the spawning parent's runner-close observation; if a restart leaves it pending, preserve evidence and seek native tooling support rather than approval/restart loops. Never remove unknown/live locks, alter journals to fabricate approval or switch models to bypass a failure. Unsupported old journals remain preserved and require manual native-worker inspection before a fresh session after a full Pi restart. Old running sessions and their per-file approval dialogs are not hot-migrated. Task-check failures reuse bounded corrections; final-check failures block because automatic task attribution is unavailable.

Release scans detect common secret patterns but are not exhaustive. See [release guidance](docs/releasing.md).

## Browser verification and evidence-only recovery

`delivery-verifier` has native read/grep/find/ls/bash, no edit/write/delegation tools, and uses the exact displayed coder model route. Approved shell commands remain trusted account-level execution, not an OS sandbox. Source/index/HEAD snapshots must remain unchanged across probes and verification; ignored files, test-data mutations and external effects are not comprehensively sandboxed. No dependency installation, browser download, production interaction, spending or credential retrieval is authorized. Agent/configuration overrides remain trusted.

Artifact reads accept only declared flat relative names in the exact run-owned directory outside source; symlink ancestors, symlink files, hardlinks, arbitrary paths, oversized files and hash mismatches fail closed. Text files are capped at 16 KiB each and 32 KiB aggregate; images at 2 MiB each, all artifacts at 4 MiB. Hash receipts bind source/task/round/phase and named scenario command exits. Verifier receipts are native structured worker claims, not independent OS-level attestation of shell effects. Bounded sanitized text is supplied directly to reviewers; binary images are hashed, not automatically embedded.

Capture only explicitly permitted nonsecret data. Raw cookies, credentials, child-login tokens, token-bearing URLs and raw traces are forbidden by default. Sanitization strips common secret headers/assignments and URL query/fragment data from reviewer text, but is defense in depth, not a guarantee that arbitrary output is safe. Raw artifacts remain private local evidence; do not publish them.

Recovery proposal is inspection-only and freezes approved product tasks/routes. Execution needs fresh approval, successful same-source coder/check checkpoint, typed recoverable failure, exact observed native closure and current retained lock fence. One attempt per task/source, including infrastructure failure; new concrete defects stop without current-task coder replay. Old journals are not silently upgraded. Recovery keeps the lease while blocked so stale journal copies cannot replay accepted work. Explicit settled OFF releases that lease and durably invalidates recovery; ON cannot restore authority after unmanaged handoff. Release failure keeps coordination ON. No automatic retry, replacement from arbitrary text, native revival, model substitution or publishing.
